# Imago【压缩转换】功能详细设计文档

## 1. 功能概述 (Overview)

【压缩转换】是 Imago 的核心功能之一，旨在通过先进的浏览器端压缩算法，在保持视觉质量的同时，最大限度地减小图片文件体积，并支持多种现代图片格式的互转。该功能完全在本地运行，确保用户数据的隐私与安全。

---

## 2. 核心架构与分层 (Architecture)

功能实现遵循 Imago 的“智能路由”架构，分为：视图层、配置层、分发层、引擎层。

- **视图层 (`CompressView.vue`)**：负责图片列表展示、处理状态反馈（进度条、状态胶囊）及结果对比弹窗。
- **配置层 (`AppExportSettings.vue`)**：统一的参数调节面板，支持专家模式下的深度定制。
- **分发层 (`dualEngine.ts`)**：根据目标格式与浏览器支持度，自动将任务分发至最合适的底层引擎。
- **引擎层**：
  - **Native 引擎 (`compressEngine.ts`)**：基于 `browser-image-compression`，利用原生 Canvas API 实现极速处理。
  - **Wasm 引擎 (`wasmEngine.ts`)**：基于 jSquash (WebAssembly)，提供 AVIF、JXL、JPEG-LI 等次世代格式的碾压级编码能力。

---

## 3. 核心功能逻辑 (Core Logic)

### 3.1 智能分发策略 (Intelligent Routing)

`dualEngine` 采用“性能优先，格式保底”的策略：

- **首选原生**：对于 JPEG、PNG、WebP 等浏览器原生支持较好的格式，路由至 Native 引擎，以获得最佳的内存占用和处理速度。
- **强制 Wasm**：
  - 次世代格式（AVIF, JXL, WebP2）统一走 Wasm 编码。
  - **JPEG-LI**：虽然输出为 JPEG 兼容，但为了应用更高级的 MozJPEG 优化算法，强制走 Wasm 路径。

### 3.2 压缩策略模式

支持两种核心压缩模式：

1. **画质优先 (Quality-First)**：
   - 用户设定 0.1 - 1.0 的质量系数。
   - 针对不同格式设置了“官方推荐值”（如 WebP 75%，AVIF 55%），在 UI 中以**蓝色呼吸灯圆点**提示。
2. **指定体积 (Target-Size)**：
   - 用户设定目标文件大小（KB）。
   - Wasm 引擎会进行最多 3 次迭代编码尝试，动态调整参数以尽可能接近目标体积。

### 3.3 格式支持与兼容性检测

利用 `formatSupport.ts` 进行前置环境校验：

- **动态回退**：如果用户选择了浏览器不支持原生导出且 Wasm 引擎也无法处理的格式（极少数情况），系统会报错并拦截，防止静默回退导致的数据误导。
- **JPEG-LI 特殊处理**：识别该格式为高阶 JPEG 优化，在 UI 展示上与标准 JPEG 区分，但在底层处理时确保其二进制流的兼容性。

## 4. UI/UX 深度设计 (UI/UX)

### 4.1 统一导出组件 (`AppExportSettings.vue`)

- **功能集成**：在一个组件内集成了格式选择、模式切换、质量/体积滑块、宽高分辨率限制。
- **PNG 深度定制**：当切换至 PNG 时，UI 自动适配显示“最大颜色数”和“编码精细度（Effort）”滑块，替代通用的质量滑块。
- **即时联动**：切换格式时，滑块会自动跳转至该格式的推荐数值，减少用户心智负担。

### 4.2 视觉反馈链路

- **处理状态胶囊**：`ImageCard` 底部实时显示 `Wait` (空闲)、`Processing` (处理中)、`Ready` (完成)。
- **智能对比 (Comparison)**：
  - **实时倍镜**：鼠标悬停在卡片上时，显示“BEFORE/AFTER”圆形放大镜，实时观察纹理细节差异。
  - **双栏弹窗**：点击对比按钮开启全屏 Modal，展示完整的原图与处理图参数（体积、分辨率）对比。
- **体积缩减百分比**：处理完成后，卡片左上角直观展示体积缩减比例，若体积变大则显示“已跳过”。

---

## 5. 技术实现细节 (Technical Details)

### 5.1 并行计算与性能

- **多线程加速**：Native 引擎利用 Web Worker 进行图片编码，避免阻塞浏览器 UI 渲染。
- **Wasm 异步加载**：jSquash 的编解码模块按需动态导入（Dynamic Import），首屏仅加载极小体积的逻辑框架。

### 5.2 元数据缝合 (Metadata Injection)

- **EXIF 保护**：在 Wasm 和 Native 处理流的最后阶段，利用 `metadata.ts` 提取原图的 EXIF 二进制片段并缝合到新生成的 Blob 中，确保 GPS、拍摄时间等信息不丢失。

### 5.3 鲁棒性设计

- **防“倒车”机制**：如果处理后的文件体积反而大于原图，系统会自动保留原始 File 对象，并在 UI 提示用户。
- **内存安全**：`imageStore` 负责在图片移除或组件销毁时，严格执行 `URL.revokeObjectURL`，防止 Blob 对象长期驻留内存导致浏览器崩溃。

---

## 6. 数据流 (Data Flow)

1.  **输入**：用户拖入或选择文件 -> `imageStore.addImages` 创建任务对象。
2.  **配置**：用户在 `AppExportSettings` 调整参数 -> 同步至 `CompressView` 的响应式状态。
3.  **分发**：点击“开始压缩” -> 遍历选中 ID -> 调用 `dualEngine(file, options)`。
4.  **处理**：引擎进入 Web Worker 或 Wasm 容器执行编码 -> 产出 Blob。
5.  **输出**：更新 `imageStore` 对应项 -> UI 状态切换为 `done` -> 用户点击下载或“导出全部（ZIP）”。
